# Аудит CyberpunkCharSheetG — Cyberpunk RED и ошибки приложения

Дата: **23 октября 2026 года**. Проверенная ревизия: `18abd1c`.

**Вывод: проект собирается, но его автоматическим расчётам и сохранению данных пока нельзя доверять без ручной проверки. Полное соответствие Cyberpunk RED со всеми дополнениями не подтверждается.** Ниже — 24 группы подтверждённых проблем. Отсутствие необязательного модуля из DLC само по себе не объявляется нарушением основных правил.

Игровой код не изменён. Добавлены только этот отчёт, диагностический стенд и результаты в `audit/`. Реальные сохранения браузера не использовались и не изменялись.

## Проверка и границы доказательств

- `npm run build`: успешно, TypeScript и production-сборка проходят. Предупреждение: JS bundle около 1,75 MB, gzip около 473 KB.
- `node audit/reproduce.cjs`: 31 диагностическая проба; результаты — [results.json](./results.json). Стенд транспилирует и исполняет исходные TS/TSX-модули. Для событий компонентов используется небольшой имитатор React hooks/JSX, звук отключён, LocalStorage заменён памятью процесса, броски фиксированы.
- Это **не браузерные end-to-end тесты и не 31 успешно пройденный тест соответствия**: стенд фиксирует фактические значения, включая ошибки. Код завершения 0 означает отсутствие ошибок самого диагностического стенда. SHA-256 загруженных исходных модулей записаны в `SOURCE_MANIFEST`.
- В `package.json` нет команды тестирования; существующих автоматических тестов в исходниках не найдено.
- Полноценный браузерный прогон не выполнен: встроенный браузер не смог подключиться к локальному dev server (`ERR_CONNECTION_TIMED_OUT`). Поэтому визуальные, мобильные, печатные и собственно React lifecycle-дефекты не считаются проверенными.
- Для базовых правил использован находящийся в проекте `corebook.txt`, с номерами **напечатанных страниц**, и опубликованные RTG FAQ/errata. Сам перевод не считаю безошибочным; спорные расхождения перевода без независимого подтверждения в находки не включены.
- Онлайн проверены официальный индекс загрузок RTG, FAQ, errata, актуальные изменения Black Chrome/оружия, сведения о новых DLC и Interface RED. Полные тексты всех платных книг в проекте отсутствуют. Построчную сверку каждого предмета со всеми платными изданиями этот аудит **не заявляет**.

P1 — потеря/порча данных или существенная ошибка основного игрового действия. P2 — ограниченная ошибка правила, состояния либо неполная автоматизация с вводящим в заблуждение результатом.

## Данные и технические ошибки

### A01 · P1 · Импорт может стереть коллекцию и оставить пустой экран

Место: [App.tsx:174](../src/App.tsx#L174), [storage.ts:117](../src/utils/storage.ts#L117).

Массив из JSON устанавливается как вся коллекция без проверки элементов и без проверки непустоты. Импорт `[]` заменяет всех персонажей пустым массивом; `App` возвращает `null`, а эффект сохранения записывает новую коллекцию. Стенд: `MALFORMED_BACKUP` → `characters=[]`, `blankScreen=true`. Одиночный импорт проверяет только наличие `id`, `name`, `stats`: отсутствующие `armor`, `skills`, `roleAbilities` затем ломают компоненты. При ошибке чтения LocalStorage функция загрузки также может заменить повреждённые, но ещё пригодные для восстановления данные новыми персонажами. Нужны проверка полной структуры до замены и сохранение исходного повреждённого значения для восстановления.

### A02 · P1 · Перезагрузка уничтожает результат терапии

Место: [storage.ts:33](../src/utils/storage.ts#L33), [roleUtils.ts:124](../src/utils/roleUtils.ts#L124).

Загрузчик ограничивает Humanity значением `EMP*10 - сумма installation HL`, а интерфейс и терапия — `EMP*10 - постоянное снижение максимума`. При EMP 6, Neural Link и Interface Plugs законный восстановленный максимум равен 56; после сохранения и загрузки получается **46**. Стенд: `HUMANITY_RELOAD`. Причина — две разные формулы одного инварианта; правила терапии: Core p.230. Загрузка должна использовать тот же расчёт максимума, что и остальные операции.

### A03 · P1 · Старый расчёт урона применяется к другому персонажу

Место: [DamageCalculatorModal.tsx:52](../src/components/DamageCalculatorModal.tsx#L52), [DamageCalculatorModal.tsx:195](../src/components/DamageCalculatorModal.tsx#L195).

Состояние результата сохраняется после закрытия модального окна. При смене персонажа и повторном открытии старый результат доступен для применения: абсолютные `newHp`/`newSp` рассчитывались для прежнего листа, но записываются в текущий. Стенд: `STALE_DAMAGE_CHARACTER` — расчёт по SP 0 переносится на другого персонажа с SP 18 и превращает его броню в **SP 0**, снимая 15 HP. Изменение зоны/типа атаки уже сбрасывает расчёт; смена персонажа и повторное открытие должны обеспечивать ту же защиту.

### A04 · P1 · 26 оружий используют формулы, которые роллер молча подменяет

Место: [dice.ts:115](../src/utils/dice.ts#L115), [DamageCalculatorModal.tsx:85](../src/components/DamageCalculatorModal.tsx#L85), [datapoolCatalog.ts:4799](../src/data/datapoolCatalog.ts#L4799).

В каталоге встречаются `3d65d6`, `2d63d65d6`, `4d65d6` и другие склейки разных режимов. Парсер принимает только `Nd6`/`Nd6+N`, а всё остальное заменяет на **3d6** без ошибки. Стенд: `INVALID_DAMAGE_FORMULAS`, полный перечень 26 записей в JSON. Это не редкий ошибочный ввод пользователя: такие строки уже поставляются с приложением. Нужны отдельные профили атаки и явный отказ от неизвестной формулы. Кроме того, число кубов не ограничено: огромный `Nd6` способен надолго заблокировать главный поток; этот потенциально зависающий ввод намеренно не запускался.

### A05 · P1 · Структурированные параметры каталога не соответствуют самим предметам

Место: [datapoolCatalog.ts:4810](../src/data/datapoolCatalog.ts#L4810), [datapoolCatalog.ts:5230](../src/data/datapoolCatalog.ts#L5230).

Из 200 оружий **162** записаны как `Medium Pistol`. Это не само по себе доказательство ошибки каждой записи, но проверенные примеры её подтверждают: Nomad Pneumatic Bolt Gun описан как снайперская винтовка, а имеет `handgun`; Sternmeyer M-02 в своём описании требует Heavy Weapons, а поле содержит `shoulder_arms`; баллистический гарпун записан как скрываемый пистолет. Эти поля непосредственно определяют навык, выбор оружия в таблице и отображение. Стенд: `CATALOG_TRUNCATION`; примеры видны в исходниках. Исправлять следует импорт/нормализацию данных и проверенные записи, а не догадки по названию в обработчике атаки.

### A06 · P2 · При импорте каталога потеряны существенные части правил

Место: [datapoolCatalog.ts:4498](../src/data/datapoolCatalog.ts#L4498), [datapoolCatalog.ts:4526](../src/data/datapoolCatalog.ts#L4526).

У **123 из 200 оружий** `notes` имеют ровно 200 символов и обрываются внутри правила. Например, ограничения BODY/заклинивания и исключения для патронов заканчиваются посреди предложения. В девяти записях каталога имеются символы замены `�`. Стенд: `CATALOG_TRUNCATION`. Для экзотического оружия именно описание задаёт исключения из правил, поэтому такое усечение меняет игровой смысл. Нужен повторный импорт полного текста с корректной кодировкой и проверкой происхождения.

## Броски, бой и состояния

### A07 · P1 · Равенство DV ошибочно считается успехом

Место: [dice.ts:72](../src/utils/dice.ts#L72).

Используется `total >= DV`. В Cyberpunk RED требуется **превзойти** DV; при равенстве выигрывает защищающаяся сторона/сложность. Стенд: `DV_EQUALITY` — 15 против DV 15 даёт `true`, должно быть `false`. Это влияет на все проверки с указанным DV. Core pp.129,172.

### A08 · P1 · Натуральная 10 может дать успешный Death Save

Место: [dice.ts:167](../src/utils/dice.ts#L167), [App.tsx:234](../src/App.tsx#L234).

Проверяется только `d10 + penalty < BODY`, поэтому BODY 12 переживает натуральную 10. Она должна автоматически убивать независимо от BODY. Стенд: `DEATH_NATURAL_10`. Дополнительно выполнение спасброска не повышает накопленный штраф: `DEATH_COUNTER_NOT_INCREMENTED` оставляет 0 вместо 1. В интерфейсе есть ручные кнопки счётчика, поэтому последнее — недостающая связь действия со счётчиком, а не отсутствие возможности ручного учёта. Core p.188.

### A09 · P1 · Социальные навыки бросаются от исходной EMP

Место: [SkillsSection.tsx:325](../src/components/SkillsSection.tsx#L325), [roleUtils.ts:140](../src/utils/roleUtils.ts#L140).

Текущая EMP показывается правильно через Humanity, но Conversation/Human Perception берут `character.stats.EMP`. При базовой EMP 6, Humanity 20 и Conversation 2 база броска равна **8**, должна быть **4**. Стенд: `EMP_SKILL_BASE`. Текущая EMP должна применяться там, где используется характеристика, а базовая — оставаться источником максимальной Humanity. Core p.80.

### A10 · P1 · Можно бесплатно потратить несуществующую Удачу

Место: [DiceRollerModal.tsx:63](../src/components/DiceRollerModal.tsx#L63).

Число передаётся в бросок до проверки доступности. HTML `max` не ограничивает ввод программно. При Luck 1 ввод 100 даёт **+100**, Luck остаётся **1**, а поле не сбрасывается. Стенд: `LUCK_OVERSPEND`. Проверять целочисленность и диапазон нужно до броска, а списание и выдача бонуса должны быть одной согласованной операцией.

### A11 · P1 · Щит пропускает остаток уничтожившего его попадания

Место: [DamageCalculatorModal.tsx:110](../src/components/DamageCalculatorModal.tsx#L110).

Щит обрабатывается как дополнительный слой HP: 15 урона минус 10 HP щита → 5 по персонажу. По правилам щит принимает **всю атаку**, даже если уничтожен. Стенд: `SHIELD_OVERFLOW`, без критического попадания и брони. Кроме того, вычисленный остаток HP щита не записывается в `character.armor.shield`, а калькулятор использует отдельное ручное значение. Core pp.182–183. Нужно различать укрытие/щит и персональную броню.

### A12 · P1 · Перепутаны правила Brawling, Melee Weapon и Throw

Место: [meleeRules.ts:142](../src/data/meleeRules.ts#L142), [meleeRules.ts:178](../src/data/meleeRules.ts#L178), [WeaponsSection.tsx:202](../src/components/WeaponsSection.tsx#L202), [App.tsx:253](../src/App.tsx#L253).

Описания и подписи утверждают, что обычная драка игнорирует половину SP. **Brawling не игнорирует SP**, в отличие от Melee Weapon и Martial Arts. Для Throw указаны кубы безоружного урона и половина брони, хотя бросок захваченной цели наносит **BODY напрямую по HP**, без абляции. В справке Grab также разрешена защита через Evasion, хотя встречный навык — Brawling. Core pp.176–177. Общая переменная `isMelee` не должна одновременно задавать характеристику атаки и правило пробития брони.

### A13 · P1 · Завышен урон без оружия при BODY 9+

Место: [meleeRules.ts:63](../src/data/meleeRules.ts#L63), [WeaponsSection.tsx:107](../src/components/WeaponsSection.tsx#L107).

Код выдаёт BODY 9–10 → 4d6, BODY 11+ → 5d6. По базовой шкале **BODY 7–10 → 3d6; BODY 11+ → 4d6**. Стенд: `UNARMED_DAMAGE`. Также расчёт не учитывает минимум 2d6 для ударов киберрукой при низком BODY. Core pp.176,178. Исключения конкретных DLC-приёмов должны быть отдельными от базовой шкалы.

### A14 · P2 · Пороги ранений и эффективные характеристики расходятся

Место: [StatsSection.tsx:95](../src/components/StatsSection.tsx#L95), [StatsSection.tsx:606](../src/components/StatsSection.tsx#L606), [App.tsx:258](../src/App.tsx#L258).

Seriously Wounded применяется при `HP <= ceil(maxHP/2)`, тогда как порог в Core p.186 — **меньше** половины, округлённой вверх. При HP 20/40 Perception с Threat Detection даёт базу 7 вместо 9: `SERIOUS_WOUND_BOUNDARY`. Для REF/DEX/MOVE после брони отображение ограничивает минимумом 1 вместо 0 (Core p.185); расчёт навыка при этом может использовать отрицательную характеристику. При Mortally Wounded не применяется отдельный штраф **MOVE −6, минимум 1**. Стенд: `ARMOR_MINIMUM_AND_MORTAL_MOVE`. `hpMaxManual` учитывается в одних компонентах и игнорируется в оружии/роллере, из-за чего один лист получает разные состояния ранения.

### A15 · P1 · Критические травмы учитываются лишь частично

Место: [DamageCalculatorModal.tsx:164](../src/components/DamageCalculatorModal.tsx#L164), [DamageCalculatorModal.tsx:146](../src/components/DamageCalculatorModal.tsx#L146), [InjuriesSection.tsx:144](../src/components/InjuriesSection.tsx#L144).

При повторе уже активной травмы нет переброса: новая травма теряется, `DUPLICATE_CRITICAL` оставляет одну вместо двух (Core p.187). Персонаж с HP 0 при новом ранящем попадании без двух шестёрок не получает обязательную травму и +1 к Death Save: `MORTAL_INCOMING_DAMAGE` (Core p.188). Активная Cracked Skull не меняет множитель головы с 2 на 3: `CRITICAL_HEAD_MULTIPLIER` даёт 18 вместо 27. Большинство штрафов активных травм, включая базовый Death Save +1, хранятся как текст и не участвуют в автоматических бросках. Нельзя считать включение чекбокса полным применением эффекта травмы.

### A16 · P2 · Бонусы оружия, Solo и имплантов не доходят до расчёта

Место: [App.tsx:261](../src/App.tsx#L261), [App.tsx:276](../src/App.tsx#L276), [DataPoolShopModal.tsx:231](../src/components/DataPoolShopModal.tsx#L231).

База атаки содержит характеристику, навык, броню и ранение; **Precision Attack и Excellent quality отсутствуют**. Стенд: `ATTACK_IGNORES_SOLO_QUALITY_MODS` — база 9 вместо 11 при Precision 3 и Excellent weapon, даже без учёта временного REF +2 в сохранении. Spot Weakness/Damage Deflection не связаны с уроном; Kerenzikov не участвует в инициативе; Grafted Muscle и Subdermal Armor представлены описанием, а не применёнными эффектами. Покупка оружия также не переносит `quality` в лист. Эти эффекты можно вести вручную, но автоматизация сейчас их не подтверждает. Core pp.146,340; соответствующие записи киберware.

### A17 · P1 · Таблица дистанций атакует случайно выбранным оружием и неправильным навыком

Место: [WeaponsSection.tsx:532](../src/components/WeaponsSection.tsx#L532), [initialData.ts:489](../src/data/initialData.ts#L489).

Поиск выполняется по первому слову категории, а при неуспехе берётся первое оружие персонажа. Нажатие `Autofire (Rifle)` запускает атаку **Heavy Pistol / Handgun против DV 22**: `RANGE_ATTACK_WRONG_SKILL`. Режим Autofire не передаётся в обработчик, поэтому нет перехода на навык Autofire и урон `2d6 × min(превышение DV, лимит оружия)`. Кнопка расхода 10 патронов существует отдельно и этого не исправляет. Кроме того, в строке Autofire SMG потеряна DV **30 на 51–100 м**. Core p.173.

## Персонаж и ролевые способности

### A18 · P1 · Смена роли безвозвратно заменяет выученные навыки

Место: [StatsSection.tsx:140](../src/components/StatsSection.tsx#L140).

Смена выпадающего списка заменяет все штатные навыки стартовым Streetrat-пакетом новой роли. Стенд: `ROLE_CHANGE_REPLACES_EARNED_SKILLS` — Handgun 10 становится 6. Автосохранение закрепляет потерю, штатной отмены нет. Это опасно даже для обычного исправления роли в существующем листе; мультикласс также не должен заменять навыки и предыдущие способности (Core p.143). Нужны отдельные операции выбора/добавления роли и явно обозначенного применения стартового шаблона.

### A19 · P1 · Streetrats и Edgerunners не воспроизводят заявленные методы генерации

Место: [roleTemplates.ts:29](../src/data/roleTemplates.ts#L29), [CharacterWizardModal.tsx:176](../src/components/CharacterWizardModal.tsx#L176).

Вместо десяти строк официальной таблицы роли используются пять других наборов для пар результатов. Для Edgerunners выполняется один бросок на весь набор, хотя метод требует отдельный бросок **для каждой характеристики**. Streetrat-навыки также отличаются от готовых таблиц: например, Solo Concentration 4/First Aid 4 против официальных 2/6. Суммы всех десяти пакетов действительно равны 86 — стенд `STREETRAT_SKILLS` это подтверждает, но одна сумма не доказывает соответствие шаблону. Core pp.74–77,86–89.

### A20 · P1 · Конструктор выдаёт бесплатные предметы и принимает незаконченную сборку

Место: [CharacterWizardModal.tsx:250](../src/components/CharacterWizardModal.tsx#L250), [CharacterWizardModal.tsx:365](../src/components/CharacterWizardModal.tsx#L365), [CharacterWizardModal.tsx:1182](../src/components/CharacterWizardModal.tsx#L1182).

Point-Buy без единой покупки создаёт SP 11 на голове и теле, оставляет **2550 eb** и всего **28 потраченных очков навыков**: `WIZARD_FREE_ARMOR`. Купленный за 100 eb щит не попадает в `armor.shield`: `WIZARD_SHIELD_LOST`. Несколько выбранных бронежилетов оплачиваются, но сохраняется лишь первый; пакетный список `equipment.gear` заменяется общими Agent/Ammo. Финализация не проверяет сумму характеристик/навыков, обязательные минимумы и бюджет. Бесплатный культурный язык 4 не создаётся отдельным навыком: вместо него везде увеличен Streetslang, который вообще может совпасть с культурным языком только при специальном выборе, а не автоматически. Edgerunner позволяет редактировать все навыки, а не установленный список своей роли. Core pp.45,85,88–90,98–105.

### A21 · P2 · Один ранг навыка открывает все стили Martial Arts; часть приёмов бросается неверно

Место: [character.ts:300](../src/types/character.ts#L300), [WeaponsSection.tsx:112](../src/components/WeaponsSection.tsx#L112), [WeaponsSection.tsx:250](../src/components/WeaponsSection.tsx#L250), [meleeRules.ts:260](../src/data/meleeRules.ts#L260).

Есть один `martial_arts` и переключатель стиля. Переключение открывает другой стиль с тем же уровнем, без его отдельной покупки, что противоречит Core p.178 и принципу расширения форм в Cyberfists of Fury. В Karate Armor Breaking Strike ошибочно требуется Brawling вместо **Melee Weapon** (Core p.179). Judo Counter Throw сразу бросает кубы урона, пропуская DV15 и правило Throw; Bone Breaking Strike/Flying Kick тоже ведут прямо в урон. В Boxing Knockout штраф −5 одновременно включён в базу и передан модификатором: в итоге −10. Последнее — арифметическое дублирование даже без оценки корректности самого DLC-приёма. Полная проверка 23 дополнительных форм требует полного текста Interface RED v4; она здесь не заявляется.

### A22 · P2 · Tech получает неправильное количество специализаций

Место: [CharacterWizardModal.tsx:381](../src/components/CharacterWizardModal.tsx#L381), [initialData.ts:855](../src/data/initialData.ts#L855), [RoleSection.tsx:61](../src/components/RoleSection.tsx#L61).

Maker 4 создаёт суммарно **4**, а не **8** рангов специализаций: `TECH_STARTING_SPECIALTIES`. Каждый ранг Maker даёт по рангу **в двух разных** специализациях (Core p.147). Редактор затем разрешает увеличивать специализации без связи с Maker rank. Для Medtech также отсутствует проверка общего бюджета распределения; без полного отображения дерева специализаций нельзя считать произвольные числовые поля корректной моделью Medicine. Исправление должно хранить/проверять распределение, а не просто ограничить отдельное поле числом 10.

### A23 · P2 · Удаление киберware автоматически возвращает текущую Humanity

Место: [CyberwareSection.tsx:103](../src/components/CyberwareSection.tsx#L103), [roleUtils.ts:139](../src/utils/roleUtils.ts#L139).

Режим удаления с маркировкой CPR сразу добавляет 2/4 к текущей Humanity. Удаление освобождает **предел восстановления**, но не заменяет терапию и не отменяет пережитую потерю. Стенд: `CYBERWARE_REMOVE_HUMANITY_REFUND` — 46 превращается в 48 без терапии. Отдельный режим «отменить ошибочную установку» с полным возвратом допустим, если ясно обозначен. Кроме того, повсеместное обрезание текущей Humanity до 0 не позволяет сохранять отрицательные значения и различать их от 0; это существенно для правил киберпсихоза и для собственной ветки `humanityCurrent < 0` в приёме Panzerfaust. Core pp.230–232. Исключения новых имплантов нельзя определять только категорией и `humanityCost`.

## Нетраннинг и DLC

### A24 · P1 · NET-автоматизация и импорт дополнений дают неверные числовые результаты

Места: [initialData.ts:504](../src/data/initialData.ts#L504), [NetrunnerSection.tsx:55](../src/components/NetrunnerSection.tsx#L55), [App.tsx:301](../src/App.tsx#L301), [datapoolCatalog.ts:4829](../src/data/datapoolCatalog.ts#L4829).

Нетраннинг:

- Sword имеет ATK **2** вместо **1**, REZ 7 вместо 0; эффект не различает **3d6 против Black ICE** и **2d6 против обычной программы**. Speedy Gonzalvez ошибочно описан как ускорение перемещения по узлам вместо Speed-проверок. Core pp.203–204.
- Установленные Eraser/SeeYa не добавляют свои +2 в Cloak/Pathfinder; wound penalties также не доходят до Interface. `NET_BOOSTER_AND_WOUNDS`: Interface 4, SeeYa установлен, HP 0 → база 4 вместо 2. Применимость wound penalties к Interface подтверждена официальным FAQ v1.3, p.2. Установка программы и её активация сейчас также не моделируются как разные состояния, поэтому корректный учёт активного эффекта невозможен.
- Проверок предела установки нет; Black ICE считается одной записью/слотом, а требует двух. Hardware и программы имеют независимые ёмкости, хотя базовая дека использует общий пул слотов. Не представлены все поля Black ICE и жизненный цикл rezzed/derezzed. Это требует исправления модели, а не только подписи счётчика. Core pp.203,207–209.

Актуальность DLC-данных:

- Arasaka WAA: описание уже говорит **35 патронов**, но структурированная ёмкость — **30**. Июльская Weapon Rebalance 2026 прямо устанавливает 35; это проверенное расхождение с действующей errata.
- Две записи Militech Mastiff стоят 500 и 1000 eb; Black Chrome v1.5 устанавливает **500**. Значит, исправление дошло не до всех дублей.
- Westwood назван Excellent в тексте, но `quality` не задан; даже после исправления ATK-обработчика каталог продолжит терять бонус.
- Отдельные текстовые пометки об удалении Exotic уже присутствуют. Следовательно, каталог не просто «старый»: обновления применены **частично**, а текст и машинные поля разошлись.

## Что подтверждено как работающее

`BASELINE_CORRECT` и `STREETRAT_SKILLS` подтверждают базовую HP-формулу, одно дополнительное d10 при натуральной 10 без цепочки взрывов, отдельный d10 Death Save без обычной механики критического успеха, постоянное снижение предела Humanity на 2/4 в основном helper, сумму 86 очков в каждом из десяти записанных Streetrat-пакетов и корректную строку дистанций Assault Rifle. `NET_ACTIONS_RANK_3_CORRECT` подтверждает 2 NET Actions при Interface 3; интервалы 1–3/4–6/7–9/10 в этом месте верны. Отдельный +5 critical damage в калькуляторе обходится без ошибочного удвоения при попадании в голову и может наноситься без пробития SP — эти части алгоритма не следует ломать при исправлении других ошибок.
